# PayHub Merchant — iOS app

The native iPhone companion app for **PayHub** merchants and shop (sub-merchant)
users. Sign in (including self-hosted / on-prem installs), watch your dashboard,
create and follow up on pay-links, and manage push notifications — all on top of
the official [`payhub-swift`](../../sdks/swift) SDK's bearer-token merchant client
(`PayhubMerchantClient`).

> **This is an app, not one of the SDK mirrors.** The `sdks/<lang>/` trees in
> this monorepo are mirrored to public per-language GitHub repos with their own
> publish pipelines. **None of that machinery applies here.** To ship this app,
> move `apps/merchant-ios/` to its own repository — see
> [Shipping it](#shipping-it-standalone-repo) below.

## What's in it

| Area | Screens |
| --- | --- |
| **Bootstrap** | Launch splash → reads the Keychain token pair → `auth.me()` → main tabs, or → Login on auth failure. |
| **Auth** | Login (server URL in an "Advanced" disclosure, merchant code, optional shop code, username, password) · MFA challenge · Forgot-password sheet · Accept-invite (deep link `payhub://accept-invite?token=…&m=…&u=…&s=…`). |
| **Dashboard** | Counter cards (paid + volume, in-flight, active pay-links, needs-follow-up) · 24h / 3d / 7d window picker · "other outcomes" list · per-shop breakdown for parent merchants (best-effort raw `?group_by=sub`). Pull-to-refresh. |
| **Pay-links** | Filterable list (All / Needs follow-up / Active / Paid / Expired / Cancelled) with cursor paging · Create sheet (amount, description, customer phone, PSP allow-list, expiry, auto-generated order ref, `ShareLink` confirmation) · Detail (re-share / extend / clone / cancel — gated on a write role). Pull-to-refresh. |
| **More** | Profile + entitlements · Push-notifications toggle (→ `UNUserNotificationCenter` + APNs registration + raw `POST /merchant/devices`) · Request password reset · Sign out · App/server footer. |

### Architecture

- **iOS 16+**, modern SwiftUI: `NavigationStack` per tab in a root `TabView`,
  sheets, `.refreshable`, `ShareLink`, `confirmationDialog`/`alert`, SF Symbols.
- **State management:** `@MainActor final class … : ObservableObject` view models
  with `@Published` (consistent throughout — chosen over the iOS-17 Observation
  framework so the app runs on iOS 16). No business logic in views.
- **`MerchantRepository`** (`@MainActor`) — owns the `PayhubMerchantClient`
  (rebuilt when the server URL or token pair changes), wires `onTokensRefreshed`
  to the Keychain so transparent refresh persists, maps `PayhubError` → a
  friendly `AppError`, and publishes an `authState` the UI watches.
- **`KeychainTokenStore`** — the `TokenPair` as JSON in a `kSecClassGenericPassword`
  item (service `ly.payhub.merchant`, `kSecAttrAccessibleAfterFirstUnlock`).
  Non-secret prefs (server URL, push flag, login pre-fill) are in `UserDefaults`
  via `AppSettings`.
- **`MerchantRawAPI`** — a tiny `URLSession` client for the few `/merchant/*`
  endpoints **not** in the 1.1.0 SDK: `POST`/`DELETE /merchant/devices` and
  `GET /merchant/dashboard?group_by=sub`. Pulls a fresh access token per call.
- **Push** — `AppDelegate` (`@UIApplicationDelegateAdaptor`) handles the APNs
  token callback (→ register the device), notification-tap routing (deep-link to
  a pay-link), and foreground presentation; `PushManager` coordinates
  authorization + the toggle state.
- **Theming** — amber `AccentColor` (light/dark) in `Assets.xcassets`,
  `Brand.swift` palette, app icon (`Icon-1024.png` / `Icon-1024-dark.png`)
  generated from `web/public/favicon-512.png` (the PayHub mark composited onto an
  opaque background — iOS icons can't have alpha).

### Known gaps — pending `payhub-swift` 1.2

The 1.1.0 SDK covers **auth, pay-links, and `reports.dashboard`** — nothing else.
So this app does **not** (yet) have: a merchant-payments list, change-password,
in-app MFA management, settlements, or sub-merchant management. Those are marked
with `// TODO(payhub): needs SDK 1.2 …` where the seam is, rather than shipped
half-broken. The dashboard's per-shop breakdown also depends on the server
returning `sub_breakdown` from `?group_by=sub`; the app shows a notice if it
doesn't.

## Building it

There is **no `.xcodeproj` in the repo** — it's generated by
[XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` (hand-authoring
an `.xcodeproj` is unmaintainable; `.gitignore` excludes it).

```bash
cd apps/merchant-ios
brew install xcodegen          # one-time
xcodegen generate              # → PayHubMerchant.xcodeproj
open PayHubMerchant.xcodeproj  # build & run in Xcode
```

Or from the command line:

```bash
xcodebuild -scheme PayHubMerchant \
  -destination 'platform=iOS Simulator,name=iPhone 15' \
  build test
```

At the login screen, enter your **server URL** (default `https://app.payhub.ly`;
change it for a self-hosted install), **merchant code**, optional **shop code**
(for sub-merchant users), **username**, and **password**.

### The `payhub-swift` dependency

`project.yml` currently pulls the SDK from the **in-repo copy** via a local
`path:`:

```yaml
packages:
  Payhub:
    path: ../../sdks/swift
```

Once `payhub-swift` **1.1.0** is published to the `safwatech/payhub-swift` GitHub
mirror, switch that to a versioned remote dependency:

```yaml
packages:
  Payhub:
    url: https://github.com/safwatech/payhub-swift
    from: 1.1.0
```

(That's also a prerequisite for the standalone repo, which won't have
`../../sdks/swift` to point at.)

## Apple Developer prerequisites

To run on a device / distribute, you need:

- An **Apple Developer account** (an Org account for App Store / TestFlight).
- An **App ID** `ly.payhub.merchant` with the **Push Notifications** capability
  enabled. (Set `DEVELOPMENT_TEAM` in `project.yml` — it's an empty placeholder —
  or override it in Xcode / CI.)
- An **APNs authentication key** (`.p8`) configured on the **PayHub server side**
  (`_ApnsNotifier`) so it can send pay-link reminders. The app itself ships no
  `.p8`, no provisioning profile, and no `aps-environment` entitlement file —
  Xcode injects the entitlement from the provisioning profile once you enable the
  Push capability on the target. **Never commit any of these secrets.**

### TestFlight

The CI workflow (`.github/workflows/ci.yml`) has a disabled `release` job stub
that archives the app and is wired (commented) for a `fastlane pilot upload` /
`xcodebuild -exportArchive` + `altool` flow. Enable it in the standalone repo
and add the App Store Connect API key secrets (`APP_STORE_CONNECT_API_KEY_ID`,
`…_ISSUER_ID`, `…_KEY_P8`).

## Shipping it (standalone repo)

This directory lives in the PayHub monorepo for convenience while it's being
built, but **to ship it you must move it to its own repo**, e.g.
`safwatech/payhub-merchant-ios`:

```bash
# From the monorepo root, one option:
git subtree split --prefix=apps/merchant-ios -b merchant-ios-export
# …then push that branch to the new repo as `main`, or just copy the directory.
```

After the move:

1. Switch the `payhub-swift` dependency in `project.yml` to the versioned `url:`
   form (above).
2. Set `DEVELOPMENT_TEAM` and add the signing / App Store Connect secrets.
3. The `.github/workflows/ci.yml` here becomes the standalone repo's CI (it's
   inert in the monorepo — no macOS runner there). Flip the `release` job's
   `if:` to a tag/release trigger.

The monorepo-side SDK-mirror pipelines (`sdks-*.yml`, the `safwatech/payhub-*`
mirrors, shared test-vectors symlinks, etc.) have **nothing to do with this app**
— don't try to fit it into that mould.

## Note on this scaffold

It was authored in an environment **without Xcode or a Swift toolchain**, so it
has **not been compiled or run** — the code is written to be correct and
idiomatic, and relies on Xcode / the standalone repo's CI to build. Expect to
shake out the usual first-build nits (a missing `import`, a `@ViewBuilder`
quirk). The icon PNGs are generated programmatically from the PayHub mark and are
fine as placeholders; swap in a designed icon set before App Store submission.
